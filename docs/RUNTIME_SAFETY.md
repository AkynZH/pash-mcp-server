# Runtime Safety Pattern: Surgical Process Cleanup by Port

## Описание аварии
В предыдущих версиях скриптов тестирования и очистки портов использовались глобальные команды принудительного завершения процессов по имени образа (например, `taskkill /F /IM node.exe`). Поскольку агентская сессия Qwen Code сама работает через `node.exe`, а фоновые задачи используют `python.exe` или `uvicorn.exe`, такие команды приводили к немедленному обрыву текущей сессии, потере контекста и невозможности завершить задачу.

## Почему сессия слетала
Агентская среда выполнения (Qwen Code CLI) и процессы сборки жестко зависят от запущенных экземпляров `node.exe` и `python.exe`. Глобальное убийство процессов по имени образа (`/IM`) не различает целевой процесс тестового сервера и системный процесс IDE/агента. Это приводило к cascade-failure рабочей среды.

## ⛔ Запрещённые команды (Красная зона)
Категорически запрещено использовать в коде или вручную:
- `taskkill /F /IM python.exe`
- `taskkill /F /IM node.exe`
- `taskkill /F /IM qwen.exe`
- `taskkill /F /IM uvicorn.exe`
- `subprocess.run(["taskkill", "/F", "/IM", ...])`
- Любые формы глобальной очистки процессов по имени образа.

## ✅ Правильный паттерн очистки (Surgical Cleanup)
Разрешено завершать **только** конкретные процессы, слушающие целевые порты, через точный поиск по PID:
1. Выполнить `netstat -aon`.
2. Найти строки со статусом `LISTENING` для целевых портов: **8770, 8769, 8765**.
3. Извлечь PID из последней колонки.
4. **Защита от самоубийства:** Если найденный PID совпадает с `os.getpid()` (текущий процесс) или `os.getppid()` (родительский процесс) — **ПРОПУСТИТЬ** (SKIP). Также пропускать PID 4 (System).
5. Выполнить `taskkill /F /PID <найденный_pid>`.
6. Тестовый скрипт (`test_connect.py`) должен завершать только собственный `server_proc` (созданный через `subprocess.Popen`), а не сторонние процессы.

## Проверочный чеклист перед запуском тестов
- [ ] В `clean_ports.py` отсутствуют команды `taskkill /IM`.
- [ ] В `clean_ports.py` реализована проверка `os.getpid()` и `os.getppid()`.
- [ ] В `test_connect.py` используется только вызов `clean_ports.py` для очистки, без собственных глобальных `taskkill`.
- [ ] В `src/sse_server.py` файл логов демона (`log_file`) открывается без контекстного менеджера `with` (или сохраняется ссылка), чтобы `subprocess.Popen` не падал с ошибкой `I/O operation on closed file`.
- [ ] Пути `cwd` и `workspace` передаются как абсолютные.
